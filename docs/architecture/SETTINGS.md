# Settings reference

Generated by `apelora-control-plane settings` (`npm run settings:doc`) from the list the control plane itself reports at `GET /api/v1/settings`. Do not edit by hand.

Every setting is an environment variable. The control plane reads its own at start; the worker reads its own; a setting both read must be given to both. A value marked *never shown* (a secret, or the path of a certificate or key file) is not displayed by the Console or the API. Defaults apply when the variable is not set; *none* means the feature is off or the value is worked out.

## Read by the worker only

| Setting | Default | What it does |
|---|---|---|
| `APELORA_ALERT_EVALUATE_SECS` | `30` | How often built-in alert rules are evaluated (0: off) |
| `APELORA_BACKUP_POOL` | none | Pool scheduled backups are copied to |
| `APELORA_BMC_ALLOW_LAB` | none | Allows the lab-only provider that stops a Lima VM (the disposable test cluster); never in production |
| `APELORA_BMC_FENCE_AFTER_SECS` | `30` | A server Offline for this long (at least 20) is switched off through its BMC and fenced |
| `APELORA_BMC_MAP` | none | File naming each server's BMC (ADR 0014): provider (redfish, ipmi, maas), address, user, the name of its password variable and its hardware UUID (for IPMI the system GUID). No passwords in it; absent: no fencing through a BMC (never shown) |
| `APELORA_DNS_BINARY` | none | Path of the Linux apelora-dns executable the worker copies into a resolver (default: apelora-dns next to the worker) |
| `APELORA_FENCE_LOCKSPACE` | none | The shared volume group's lockspace the fence probe reads; default the only one joined |
| `APELORA_FENCE_PROBE` | `off` | How the worker reads the shared storage's leases to fence a failed server (off or ssh) |
| `APELORA_FENCE_PROBE_KEY` | none | Private key of the fence probe's forced SSH command (never shown) |
| `APELORA_FENCE_PROBE_KNOWN_HOSTS` | none | Pinned host keys of the members the fence probe reads (never shown) |
| `APELORA_FENCE_PROBE_TARGETS` | none | Where the fence probe reaches each member (member=host[:port]); default the member's address, port 22 |
| `APELORA_FENCE_PROBE_USER` | `apelora-fence` | Account of the fence probe on each member |
| `APELORA_HEALTH_FAIL_AFTER_SECS` | `20` | Failing checks for this long: unhealthy |
| `APELORA_HEALTH_RESTART_AFTER_SECS` | `60` | Unhealthy for this long: restarted |
| `APELORA_OUTBOX_SINK` | `log` | Where audit messages are relayed |
| `APELORA_PROBE_UID` | `65534` | User a module's readiness command runs as inside its instances (not root by default) |
| `APELORA_REBALANCE` | none | 1: move a stateless replica that shares a server with another of its module (off when unset) |
| `APELORA_RECOVER_AFTER_SECS` | `120` | Offline time before replicas are substituted |
| `APELORA_RESTORE_DRILL_RECORD` | none | The restore drill's result file the restore-age alert reads |
| `APELORA_SUPERVISE_SECS` | `30` | Seconds between replica supervisor passes |

## Named by other settings

These variables have names an administrator chooses, so they are not listed above. Their values are secrets: read when needed, never stored, logged or shown.

| Setting | Read by | What it does |
|---|---|---|
| `APELORA_ALERT_SECRET_<NAME>` | worker | The signing secret of an alert channel whose `secretRef` names it ([alerts runbook](../runbooks/alerts.md)) |
| `APELORA_BMC_SECRET_<NAME>` | worker | The password of a BMC whose entry in `APELORA_BMC_MAP` names it as `secretRef` ([member-failure runbook](../runbooks/member-failure.md)) |
| `APELORA_SECTOR_<CREDENTIALS>_CLIENT_CERT`, `_CLIENT_KEY`, `_SERVER_CERT` | control plane | Paths of the Incus identity and server certificate of a registered sector whose `credentials` names them ([ADR 0008](../adr/0008-sectors.md)); read when the sector is probed, never stored |

## Read by the DNS resolver

`apelora-dns` runs inside an application's resolver module, not on the servers.

| Setting | Default | What it does |
|---|---|---|
| `APELORA_DNS_RECORDS_FILE` | `/etc/apelora-dns.records` | The service names it answers (`name address` lines), read again on every query |
| `APELORA_DNS_UPSTREAM_FILE` | `/etc/apelora-dns.upstream` | The resolvers it forwards every other lookup to |
